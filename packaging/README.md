# Упаковка и запуск

Место для будущих конфигураций, сборки и установки локального MCP-пакета. Сейчас здесь нет установщика или готового плагина.

| Каталог | Будущее содержимое |
| --- | --- |
| `common/` | Правила сборки Python-пакета, состава skills, MCP-конфигурации и манифеста плагина |
| `macos/` | Запуск и сборки для Apple Silicon и Intel, подпись и подготовка к распространению |
| `windows/` | Запуск и сборки для x64, позднее проверка ARM64, подпись и установка |

Runtime и зависимости нельзя считать заранее установленными у пользователя. Разработчикам — изолированное окружение; пользовательской поставке — собственный runtime либо проверяемая установка с явными требованиями. Выбор конкретного сборщика бинарных пакетов откладывается до работающего сквозного сценария.

Сборка должна разместить общие skills в самостоятельных папках, добавить нужные платформенные справочники и указать на реально существующую точку запуска сервера. Пути внутри готового пакета не должны зависеть от расположения репозитория разработчика.

Манифесты `plugin.json`, `mcp.json` и регистрации marketplace добавляются после проверки работающего пакета и актуального формата выбранного клиента. Публикация исходников на GitHub не равна готовой установке или допуску в официальный каталог. До релиза также нужно определить лицензию проекта и проверить лицензии зависимостей.

Системные скрипты сбора принадлежат `collectors/<os>/`, а не этому каталогу. В этом слое остаются установка, сборка и запуск.

См. [архитектуру](../ARCHITECTURE.md).
